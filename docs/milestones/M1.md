# M1: Foundation (Oct 5–9)

**Exit criteria:** `docker compose up` loads the catalog, Nimbus, and history; constraints are applied; `npm test` is green; the denylist check runs in CI.

**Rules:**
- Read `docs/design/DESIGN.md` first; it is the contract.
- Write tests first for each task, from its acceptance criteria.
- Run `/verify` before marking a task done.
- Do not start the next milestone's tasks.

## T1.1: Repo skeleton

**Model:** Sonnet 5.5

**Scope:** npm workspaces (`packages/*`); TypeScript strict; vitest; eslint; Node LTS pinned in `.nvmrc`. Add `docker-compose.yml` with Neo4j **Community** (pin an exact 5.26 LTS or 2025.x/2026.x tag, with APOC and GDS versions compatible with it) via `NEO4J_PLUGINS`, a health check, and a named volume. Add `scripts/reset-demo.sh` (wipe per-deal subgraphs, reload, verify counts).

**Acceptance:** `docker compose up -d` is healthy; `RETURN gds.version()` and `RETURN apoc.version()` both succeed; `npm test` runs an empty suite green.

## T1.2: Schema DDL

**Model:** Opus 5.5

**Scope:** `config/ontology.json` per DESIGN §1.4 (labels, keys, required properties, reserved flag, relationship types and endpoints). `graph/schema.cypher`: a uniqueness constraint for every key in DESIGN §1.1, plus indexes on `deal_code` for per-deal labels, generated from or checked against `config/ontology.json`. The loader applies it one statement at a time.

**Acceptance:** A test asserts `config/ontology.json` matches DESIGN §1.1–§1.2 (23 labels). A test applies the schema twice (idempotent) and asserts that the constraint count is 23 and that each constraint matches an ontology key.

## T1.3: Data generator

**Model:** Sonnet 5.5

**Scope:** Hand-author the catalog and planted structure, and write `scripts/generate-data.ts` (fixed seed) for the generated parts, per DATA.md "Authoring vs generation". Output YAML/JSON under `data/`, plus `data/manifest.json`.

**Acceptance:** Re-running produces no git diff; a zod schema check on all data files (hand-authored and generated) passes; edge coverage on the catalog is ≥ 0.6; a test asserts the structural preconditions of P1, P2, P3, P5, and P6 are present in the data; ≥ 5 Tasks have ≥ 3 Actuals.

## T1.4: Loaders

**Model:** Opus 5.5

**Scope:** `graph/load/{catalog,deal,history}.ts` use parameterized `UNWIND` + `MERGE` on the keys, nodes first, then relationships. Records are validated with zod schemas derived from `config/ontology.json` before writing (required properties are not DB-enforced on Community).

**Acceptance:** Loading twice gives identical node and relationship counts; counts match the generator's manifest.

## T1.5: Denylist CI

**Model:** Haiku 4.5

**Scope:** `scripts/denylist-check.ts` reads `$DENYLIST_FILE` (it must live outside the repo) and greps the tracked files, case-insensitively, and also the commit messages on the branch. Add a GitHub Actions workflow that writes the `DENYLIST` repository secret to a temp file and passes it as `DENYLIST_FILE`. If the variable or secret is missing, the check **fails** with a clear message (no silent skip in CI). Locally, `npm run denylist` with no `DENYLIST_FILE` exits non-zero and says it was not run.

**Acceptance:** CI fails on a seeded test term, fails when the secret is missing, and passes on a clean tree.
