# M1: Foundation (Oct 5–9)

**Exit criteria:** `docker compose up` loads the catalog, Nimbus, and history; constraints are applied; `npm test` is green; the denylist check runs in CI.

**Rules:**
- Read `docs/design/DESIGN.md` first; it is the contract.
- Write tests first for each task, from its acceptance criteria.
- Run `/verify` before marking a task done.
- Do not start the next milestone's tasks.

| Task | Title | Suggested model |
|---|---|---|
| T1.1 | Repo skeleton | Sonnet 5.5 |
| T1.2 | Schema DDL | Opus 5.5 |
| T1.3 | Data generator | Sonnet 5.5 |
| T1.4 | Loaders | Opus 5.5 |
| T1.5 | Denylist CI | Haiku 4.5 |

## T1.1: Repo skeleton

**Model:** Sonnet 5.5

**Scope:** npm workspaces (`packages/*`); TypeScript strict; vitest; eslint; Node LTS pinned in `.nvmrc`. Add `docker-compose.yml` with Neo4j (pin an exact 5.x/2025.x tag), with APOC and GDS via `NEO4J_PLUGINS`, a health check, and a named volume. Add `scripts/reset-demo.sh` (wipe per-deal subgraphs, reload, verify counts).

**Acceptance:** `docker compose up -d` is healthy; `RETURN gds.version()` and `RETURN apoc.version()` both succeed; `npm test` runs an empty suite green.

## T1.2: Schema DDL

**Model:** Opus 5.5

**Scope:** `graph/schema.cypher`: a uniqueness constraint for every key in DESIGN §1.1, plus indexes on `deal_code` for per-deal labels. The loader applies it one statement at a time.

**Acceptance:** A test applies the schema twice (idempotent) and asserts that the constraint count matches DESIGN §1.1.

## T1.3: Data generator

**Model:** Sonnet 5.5

**Scope:** `scripts/generate-data.ts` with a fixed seed. Produce everything in DATA.md, including planted situations P1–P6. Output YAML/JSON under `data/`.

**Acceptance:** Re-running produces no git diff; a schema check on the generated files passes; edge coverage on the catalog is ≥ 0.6.

## T1.4: Loaders

**Model:** Opus 5.5

**Scope:** `graph/load/{catalog,deal,history}.ts` use parameterized `UNWIND` + `MERGE` on the keys, nodes first, then relationships.

**Acceptance:** Loading twice gives identical node and relationship counts; counts match the generator's manifest.

## T1.5: Denylist CI

**Model:** Haiku 4.5

**Scope:** `scripts/denylist-check.ts` reads `$DENYLIST_FILE` (it must live outside the repo) and greps the tracked files. Add a GitHub Actions workflow.

**Acceptance:** CI fails on a seeded test term and passes on a clean tree.
