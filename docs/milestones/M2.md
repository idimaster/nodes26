## T2.1: Planner engine (Option B)

**Model:** Opus 5.5

**Scope:** `packages/engine`: the pure functions in DESIGN §2–§2.6: recommend_strategy, classify_finding, analyze_pattern_fit (5 signals, reuse penalty, bands), instantiate_tasks, compute_schedule (Kahn; throws a cycle witness; PERT band), estimate_provenance, classify_buy_build, and cypher_template. Create `config/thresholds.json` with the shape in DESIGN §2 and read every number from it. No I/O: callers pass the thresholds in.

**Acceptance:**
- Unit tests per function, including P5 (cycle witness) and the reuse penalty (4th use of a pattern = −10).
- Data tests against `@planner/data` (no Neo4j): recommend_strategy picks `bridge` for Nimbus; analyze_pattern_fit ranks `scim-provisioning` first for P1, `cdc-replication` and `batch-etl-export` first for P2 (with each near-miss within 20 points), and `container-replatform-fastpath` first for P5; classify_buy_build gives the three P6 outcomes in `planted.yaml`.
- compute_schedule reproduces the `earliest_start`, `wave`, and `on_critical_path` values of the generated history plans.
- ≥ 90% line coverage on `engine`.

## T2.3: Neo4j MCP wiring

**Model:** Sonnet 5.5

**Scope:** `.mcp.json` (project-level, not bundled in the plugin, so tool names are `mcp__neo4j-read__…` and `mcp__neo4j-write__…`): the official Neo4j MCP server as two instances, `neo4j-read` (READ_ONLY) and `neo4j-write`. Pin an exact release. If its tool names differ from `get-schema`/`read-cypher`/`write-cypher`, update DESIGN §2, §6 and the hook matcher in the same commit. Document the install in the README.

**Acceptance:** In Claude Code, `get-schema` returns labels, and `read-cypher` refuses a write query.

## T2.4: Write guard

**Model:** Opus 5.5 (high effort)

**Scope:** `packages/guard`: the tokenizer and `validate()` implementing rules G1–G9 (DESIGN §3), plus `bin/guard-hook.ts`, the Claude Code PreToolUse adapter (reads hook JSON from stdin and returns a deny with its reason). Register it in `hooks/hooks.json` for `mcp__neo4j-write__write-cypher`.

**Acceptance:**
- One allow case and one deny case per rule; a G8 test uses a fixture GateDecision.
- Bypass tests, each denied: a forbidden keyword or label hidden in a comment or backticks, a reserved label via `apoc.merge.node`, a dynamic label `:$($x)`, `status` set to `'committed'` through a parameter or a `SET n += $props` map, a commit gate from another deal or iteration, and a `select` gate used for commit.
- Allow tests: the same keywords inside string literals, and a `CALL {…}` subquery.
- A deny is visible live in Claude Code.

## T2.5: Gate server + console

**Model:** Opus 5.5 (high effort)

**Scope:** `packages/gate`: a stdio MCP server with request_approval / await_approval (50-second long-poll) and resolve_feedback, plus a localhost HTTP endpoint for the console. It writes GateDecision, Feedback, and Override with its own driver, parsing the comment grammar in DESIGN §4. Add a minimal console panel in `viz/`. Set `MCP_TOOL_TIMEOUT` in the plugin env.

**Acceptance:** Approve, approve-except, and reject each produce exactly the specified nodes; every row of the Override grammar table produces its Override; a comment outside the grammar produces Feedback only; a timeout returns `pending`; resolve_feedback writes `RESOLVED_BY` and refuses other deals' ids; the agent cannot write reserved labels (G7).

## T2.6: Plugin, agent, skill, tool-surface check

**Model:** Opus 5.5

**Scope:** Add `.claude-plugin/plugin.json`, `agents/planner.md` (tool allowlist), and `skills/plan-integration/SKILL.md` (DESIGN §6). Add `scripts/check-tool-surface.ts`: tools referenced in skills = tools granted to the agent = tools served by the MCP servers, and the guard hook's matcher names a served tool.

**Acceptance:** The check passes, and fails on a fixture with drift (including a hook matcher that matches nothing); an end-to-end Nimbus run reaches a committed roadmap.
