**Exit criteria:** The agent plans Nimbus end to end in Claude Code. Guard denials are visible with reasons. Approve and reject are both recorded by the gate server.

## T2.1: Planner engine (Option B)

**Model:** Opus 5.5

**Scope:** `packages/engine`: the pure functions in DESIGN §2: fit (5 signals, reuse penalty, bands from `config/thresholds.json`), classify_finding, instantiate_tasks, compute_schedule (Kahn; throws a cycle witness), estimate_provenance, classify_buy_build, and cypher_template. No I/O.

**Acceptance:** Unit tests per function, including P5 (cycle witness) and the reuse penalty (4th reuse = −10); ≥ 90% line coverage on `engine`.

## T2.2: Engine MCP

**Model:** Sonnet 5.5

**Scope:** `packages/engine-mcp`: a stdio MCP server exposing T2.1 with zod schemas.

**Acceptance:** An MCP inspector lists all tools, and a sample call round-trips.

## T2.3: Neo4j MCP wiring

**Model:** Sonnet 5.5

**Scope:** `.mcp.json`: the official Neo4j MCP server as two instances, `neo4j-read` (READ_ONLY) and `neo4j-write`. Document the install in the README.

**Acceptance:** In Claude Code, `get-schema` returns labels, and `read-cypher` refuses a write query.

## T2.4: Write guard

**Model:** Opus 5.5 (high effort)

**Scope:** `packages/guard`: `validate()` implementing rules G1–G9 (DESIGN §3), plus `bin/guard-hook.ts`, the Claude Code PreToolUse adapter (reads hook JSON from stdin and returns a deny with its reason). Register it in `hooks/hooks.json` for `mcp__neo4j-write__write-cypher`.

**Acceptance:** One allow case and one deny case per rule; a G8 test uses a fixture GateDecision; a deny is visible live in Claude Code.

## T2.5: Gate server + console

**Model:** Opus 5.5 (high effort)

**Scope:** `packages/gate`: a stdio MCP server with request_approval / await_approval (50-second long-poll), plus a localhost HTTP endpoint for the console. It writes GateDecision, Feedback, and Override with its own driver (DESIGN §4). Add a minimal console panel in `viz/`. Set `MCP_TOOL_TIMEOUT` in the plugin env.

**Acceptance:** Approve, approve-except, and reject each produce exactly the specified nodes; a timeout returns `pending`; the agent cannot write reserved labels (G7).

## T2.6: Plugin, agent, skill, tool-surface check

**Model:** Opus 5.5

**Scope:** Add `.claude-plugin/plugin.json`, `agents/planner.md` (tool allowlist), and `skills/plan-integration/SKILL.md` (DESIGN §6). Add `scripts/check-tool-surface.ts`: tools referenced in skills = tools granted to the agent = tools served by the MCP servers.

**Acceptance:** The check passes, and fails on a fixture with drift; an end-to-end Nimbus run reaches a committed draft roadmap.
