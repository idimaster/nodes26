## T4.1: Iterations and memory

**Model:** Opus 5.5

**Scope:** Add the recall_memory and iteration_diff queries; skill instructions for the feedback loop (DESIGN §6 step 12); the agent resolves Feedback through the gate server's `resolve_feedback` when a change addresses it (it cannot write `Feedback` itself).

**Acceptance:** P4 end to end: rejection → iteration 2 → the diff lists the change, with its feedback text.

## T4.2: Live view

**Model:** Sonnet 5.5

**Scope:** `viz/index.html`: NVL view polling the deal subgraph through a read-only session, with stable positions (incremental add), color by subgraph, and red highlighting of witnesses; host the gate console panel. Check the NVL license; fall back to a Neo4j Browser `style.grass`.

**Acceptance:** Renders Nimbus with no full relayout on update; the console works on the same page.

## T4.3: Gotcha folders 01–09

**Model:** Sonnet 5.5

**Scope:** Build each folder per GOTCHAS.md, reusing fixtures and queries; no duplicated logic.

**Acceptance:** 9 tests: before fails, after passes.

## T4.4: Golden run + replay (Tier 0)

**Model:** Opus 5.5

**Scope:** `scripts/record-session.ts` captures tool calls and results from a live run into `data/replays/nimbus-v1.jsonl`; `npm run demo:replay` re-executes the Cypher writes and the gate decisions without an LLM. Add a golden test asserting final graph counts and validator verdicts.

**Acceptance:** On a fresh database, replay produces the same counts and verdicts as the live run.
